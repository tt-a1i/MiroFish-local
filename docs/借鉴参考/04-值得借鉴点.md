# 值得借鉴点：短期、中期、长期

## 总体原则

Decitron 最值得借鉴的不是“通用决策大模型”这个包装，而是它把复杂决策拆成了更工程化的闭环：

```text
信号感知 -> 问题结构化 -> 多主体推演 -> 多情景对比 -> 方案评估 -> 持续追踪 -> 概率校准
```

MiroFish-local 的升级应遵循三个原则：

1. 不推倒重来，复用现有图谱、OASIS、报告 Agent、图谱记忆写回。
2. 不盲目泛化，优先服务传播推演、舆情研判、危机公关和公共治理。
3. 不只做漂亮报告，必须形成可比较、可复盘、可再推演的决策资产。

## 短期：1 到 4 周

短期目标是用较低工程成本，把当前“单次传播模拟”升级成“结构化传播推演报告”。

### 1. 决策问题结构化

在 Step1 的“选择推演方向”旁新增结构化表单或自动解析结果，将用户输入拆成：

- 判断对象：要判断的事件、争议、传播态势或风险。
- 时间范围：例如 24 小时、72 小时、7 天、30 天。
- 关键主体：官方、媒体、当事人、平台、KOL、公众群体。
- 核心变量：回应速度、证据强度、平台推荐、媒体跟进、反转信息。
- 可干预动作：发布声明、补充证据、平台降权、KOL 背书、法律动作。
- 目标指标：降低负面声量、避免二次峰值、提升信任恢复、压缩传播半径。

推荐落点：

- `frontend/src/components/Step1GraphBuild.vue`
- `backend/app/services/seed_analysis_service.py`
- 新增 `backend/app/services/decision_scenario_service.py`

短期收益：

- 报告更稳定。
- 后续多情景配置有数据基础。
- 用户能更清晰地表达“我要比较什么方案”。

### 2. 决策型报告模板

在 `ReportAgent` 中新增“传播决策报告”模式，固定输出：

1. 核心判断
2. 条件化结论
3. 关键变量
4. 高风险路径
5. 可干预方案
6. 待观察信号
7. 建议下一轮推演

推荐落点：

- `backend/app/services/report_agent.py`
- `backend/app/services/zep_tools.py`
- `frontend/src/components/Step4Report.vue`

短期收益：

- 报告从“趋势叙述”变成“决策建议”。
- 用户更容易把结果用于危机公关和传播策略。

### 3. 基础指标评估

基于 `actions.jsonl` 先做一批不依赖复杂 NLP 的指标：

- 总动作数
- 发帖数 / 评论数 / 转发数 / 点赞数
- 传播峰值轮次
- 首次二次扩散轮次
- Top 活跃 Agent
- Top 被引用内容
- 平台动作分布
- 关键主体响应延迟

可再加入轻量 LLM 情绪分类：

- 正向 / 中性 / 负向内容占比
- 支持 / 质疑 / 观望立场占比

推荐落点：

- 新增 `backend/app/services/simulation_metrics_service.py`
- 扩展 `backend/app/api/simulation.py`
- Step3/Step4 展示指标卡片

短期收益：

- 为多情景对比提供统一指标。
- 报告可引用量化结果，而不是只引用文本。

### 4. 情景标签与配置快照

当前“重新推演”容易覆盖旧结果。短期先支持：

- 给每次 simulation 起情景名称。
- 保存本次 simulation config 快照。
- 标记 baseline / strategy-a / strategy-b。
- 在项目维度列出多个 simulation。

推荐落点：

- `backend/app/models/project.py`
- `backend/app/services/simulation_manager.py`
- `frontend/src/components/Step2EnvSetup.vue`
- `frontend/src/views/MainView.vue`

短期收益：

- 为后续多情景对比打基础。
- 不改变 OASIS 内部即可实现。

## 中期：1 到 3 个月

中期目标是形成“多情景传播决策闭环”，让用户能定义干预方案、运行多个平行世界、比较结果差异。

### 1. 多情景对比中心

新增“情景中心”，支持：

- 从 baseline 复制一个新情景。
- 调整干预参数。
- 批量运行多个情景。
- 生成横向对比报告。

情景参数包括：

- 官方回应时间
- 初始帖子发布主体
- 平台推荐权重
- 病毒传播阈值
- 回声室强度
- 某类 Agent 立场或情绪偏置
- KOL/媒体是否介入
- 指定时间插入外部事件

推荐落点：

- 新增 `backend/app/models/decision.py`
- 新增 `backend/app/services/scenario_manager.py`
- 新增 `backend/app/services/scenario_comparison_service.py`
- 扩展 `frontend/src/components/Step2EnvSetup.vue`
- 新增 `frontend/src/components/ScenarioComparePanel.vue`

### 2. 干预机制

在模拟配置中引入 `interventions`：

```json
{
  "interventions": [
    {
      "id": "official_response_t2",
      "round": 2,
      "actor_type": "GovernmentAgency",
      "action": "CREATE_POST",
      "content": "官方回应内容",
      "expected_effect": "降低谣言扩散"
    }
  ]
}
```

干预类型：

- 内容干预：某主体发布声明或补充证据。
- 平台干预：降低推荐权重、提高病毒阈值。
- 主体干预：改变某类 Agent 的立场、活跃度、响应延迟。
- 事件干预：在某轮插入新证据、新媒体报道、新平台声明。

### 3. 外部信号追踪

把 Step1 的 Web Search 能力扩展为持续追踪：

- 信号源：Web Search、用户补充材料、新闻链接、后续报告。
- 信号状态：new / known / changed / contradicted / stale。
- 信号字段：source_url、observed_at、published_at、claim、confidence、related_hypothesis、impact_level。
- 触发规则：当信号命中某个关键变量，提醒用户更新推演。

推荐落点：

- `backend/app/services/web_search_provider.py`
- `backend/app/services/bocha_search_service.py`
- `backend/app/services/bailian_web_search_service.py`
- 新增 `backend/app/services/signal_tracking_service.py`
- 复用 `zep_graph_memory_updater.py` 的 outbox/retry 思路

### 4. 证据矩阵与反证机制

在报告工具层新增：

- `signal_search`
- `evidence_matrix`
- `scenario_compare`
- `probability_assess`

报告中固定展示：

| 假设 | 支持证据 | 反证 | 关键变量 | 当前判断 |
| --- | --- | --- | --- | --- |

这样可以避免报告只给单向结论，提升可审计性。

### 5. 概率雏形

不急于做复杂贝叶斯模型，可先做经验概率：

- 同一情景运行 N 次。
- 统计某类结果出现频率。
- 输出经验概率和置信提醒。

示例：

```text
在 10 次模拟中，负面二次峰值出现 7 次，经验概率约 70%。
关键触发因素为媒体二次跟进、官方回应延迟超过 6 小时、KOL 质疑内容被高频转发。
```

## 长期：3 到 12 个月

长期目标是形成真正的“传播推演决策引擎”，具备跨案例复盘、概率更新、策略推荐和环境扩展能力。

### 1. 概率信念与贝叶斯更新

建立 `Hypothesis` 和 `BeliefState`：

- 初始先验来自历史案例、专家设定或多次仿真。
- 新信号进入后更新概率。
- 报告展示概率变化原因。

可支持：

- 传播峰值概率
- 二次反转概率
- 官方回应有效概率
- 平台干预成功概率
- 关键群体转向概率

### 2. 历史案例库与回测

构建历史舆情事件库：

- 事件背景
- 初始信号
- 实际传播路径
- 关键拐点
- 官方/平台/媒体干预
- 实际结果

用来回测：

- 预测路径是否命中
- 风险阈值是否提前识别
- 情景排序是否合理
- 指标误差如何

### 3. 环境适配器

把 OASIS 社交仿真封装成第一个环境：

```text
SimulationEnvironment
  - SocialPropagationEnvironment
  - MarketSentimentEnvironment
  - PolicyGovernanceEnvironment
```

长期可以从传播推演扩展到：

- 金融市场情绪推演
- 公共政策影响评估
- 企业战略传播风险
- 品牌危机处置策略

### 4. 策略推荐器

在多情景比较基础上，系统自动推荐策略：

- 目标：最小化负面传播峰值。
- 约束：回应成本、时间窗口、可信证据、法律风险。
- 输出：推荐动作、执行时机、预期收益、潜在副作用。

### 5. 可视化决策工作台

前端从 5 步流程升级为项目工作台：

- 事件图谱
- 情景设计
- 运行监控
- 信号追踪
- 结果洞察
- 互动验证
- 再推演

## 优先级排序

| 优先级 | 借鉴点 | 原因 |
| --- | --- | --- |
| P0 | 决策问题结构化 | 成本低，能立刻改善后续链路 |
| P0 | 决策型报告模板 | 用户价值明显，工程风险低 |
| P1 | 基础指标评估 | 为多情景对比和概率打基础 |
| P1 | 情景标签与配置快照 | 支撑后续分支对比 |
| P2 | 多情景对比中心 | 产品价值高，但需要较多后端和前端改造 |
| P2 | 外部信号追踪 | 接近 Decitron X-Signal，但需要状态机和调度 |
| P3 | 概率信念更新 | 长期价值高，需要回测数据支撑 |
| P3 | 环境适配器 | 泛化能力强，但不宜短期启动 |
