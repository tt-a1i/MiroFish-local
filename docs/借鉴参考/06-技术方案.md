# 技术方案：传播推演决策引擎升级

## 1. 设计目标

在不推翻现有 MiroFish-local 架构的前提下，新增一层“决策推演能力”。该层复用现有图谱、人设、OASIS 仿真、行动日志、报告 Agent 和图谱记忆写回，补齐 Decitron 公开资料中值得借鉴的几个关键环节：

- 决策问题结构化
- 多情景/多策略分支
- 干预动作
- 指标评估
- 情景对比
- 外部信号追踪
- 证据矩阵与概率雏形

## 2. 总体架构

```text
Step1 事件输入
  -> SeedAnalysisService
  -> DecisionScenarioService
  -> Project.decision_context

Step2 情景设计
  -> ScenarioManager
  -> SimulationConfigGenerator
  -> InterventionPlanner

Step3 推演运行
  -> SimulationRunner / OASIS
  -> actions.jsonl
  -> SimulationMetricsService
  -> GraphMemoryUpdater

Step4 结果洞察
  -> ZepToolsService
  -> ScenarioComparisonService
  -> ReportAgent

Step5 互动验证
  -> AgentDialogueService
  -> Survey/Interview
  -> CalibrationRecord

外部信号
  -> SignalTrackingService
  -> SignalEpisodeWriter
  -> Zep/Graphiti
  -> ReportAgent signal tools
```

## 3. 新增数据模型

### 3.1 DecisionContext

用途：保存 Step1 结构化后的决策问题。

建议字段：

```python
@dataclass
class DecisionContext:
    decision_goal: str
    time_horizon: str
    target_outcomes: list[str]
    actors: list[dict]
    key_variables: list[dict]
    candidate_interventions: list[dict]
    risk_signals: list[dict]
    assumptions: list[str]
    generated_at: str
```

存储方式：

- MVP：保存到 `Project` 的新增字段 `decision_context`。
- 后续：独立 `backend/app/models/decision.py`。

相关现有位置：

- `backend/app/models/project.py`
- `backend/app/services/seed_analysis_service.py`

### 3.2 Scenario

用途：同一个项目下保存多个推演情景。

```python
@dataclass
class Scenario:
    scenario_id: str
    project_id: str
    graph_id: str
    name: str
    description: str
    base_simulation_id: str | None
    simulation_id: str | None
    config_snapshot: dict
    changed_variables: list[dict]
    interventions: list[dict]
    target_metrics: list[str]
    status: str
    created_at: str
    updated_at: str
```

MVP 可以先放在项目目录下：

```text
uploads/projects/{project_id}/scenarios/{scenario_id}.json
```

或复用当前 simulation data 目录结构。

### 3.3 Intervention

用途：描述对传播环境的干预。

```python
@dataclass
class Intervention:
    intervention_id: str
    type: str  # content / platform / actor / event / stance
    round: int | None
    simulated_hour: int | None
    target: dict
    payload: dict
    expected_effect: str
```

干预应用方式：

- 内容干预：转换为 initial_posts 或 scheduled_events。
- 平台干预：修改 `twitter_config` / `reddit_config`。
- 主体干预：修改 `agent_configs`。
- 事件干预：写入 `event_config.scheduled_events`。

### 3.4 SimulationMetrics

用途：保存每个 simulation 的指标结果。

```python
@dataclass
class SimulationMetrics:
    simulation_id: str
    scenario_id: str | None
    total_actions: int
    action_counts: dict
    platform_distribution: dict
    peak_round: int | None
    peak_actions: int
    active_agent_count: int
    top_agents: list[dict]
    top_posts: list[dict]
    sentiment_distribution: dict | None
    stance_distribution: dict | None
    secondary_peak_detected: bool | None
    generated_at: str
```

数据来源：

- `simulation_data/{simulation_id}/twitter/actions.jsonl`
- `simulation_data/{simulation_id}/reddit/actions.jsonl`
- 现有 `SimulationRunner.get_actions`、`get_timeline`、`get_agent_stats`

### 3.5 SignalObservation

用途：保存外部信号。

```python
@dataclass
class SignalObservation:
    signal_id: str
    project_id: str
    graph_id: str
    source_type: str
    source_url: str
    title: str
    summary: str
    observed_at: str
    published_at: str | None
    related_variables: list[str]
    impact_level: str
    confidence: float
    supports_hypothesis: list[str]
    contradicts_hypothesis: list[str]
    raw_payload: dict
```

写入方式：

- 保存 JSON 文件，便于 MVP 快速实现。
- 同时作为 episode 写入 Zep/Graphiti，便于报告工具检索。

## 4. 后端模块设计

### 4.1 DecisionScenarioService

文件：

```text
backend/app/services/decision_scenario_service.py
```

职责：

- 输入 seed summary、simulation_requirement、entity_hints。
- 调用 LLM 输出 `DecisionContext`。
- 做字段校验和兜底。
- 保存到 Project。

接口：

```python
class DecisionScenarioService:
    def generate_decision_context(
        self,
        project_id: str,
        seed_summary: str,
        simulation_requirement: str,
        entity_hints: list[str],
        additional_context: str = ""
    ) -> DecisionContext:
        ...
```

### 4.2 ScenarioManager

文件：

```text
backend/app/services/scenario_manager.py
```

职责：

- 创建 baseline 情景。
- 从已有情景复制新情景。
- 保存配置快照。
- 应用干预生成新的 simulation config。
- 列出项目下所有情景。

关键方法：

```python
create_scenario(project_id, base_simulation_id, name, description)
update_scenario_variables(scenario_id, changed_variables)
attach_simulation(scenario_id, simulation_id)
list_scenarios(project_id)
```

### 4.3 InterventionPlanner

文件：

```text
backend/app/services/intervention_planner.py
```

职责：

- 将用户选择的干预动作转换为 `SimulationParameters` 可识别的配置变更。
- 校验干预是否可执行。
- 记录干预与目标指标的关系。

应用逻辑：

```text
content -> event_config.scheduled_events
platform -> twitter_config / reddit_config
actor -> agent_configs
stance -> agent_configs.sentiment_bias / stance
```

### 4.4 SimulationMetricsService

文件：

```text
backend/app/services/simulation_metrics_service.py
```

职责：

- 读取 actions.jsonl。
- 计算基础指标。
- 可选调用 LLM 做情绪/立场分类。
- 生成 metrics JSON。

关键方法：

```python
generate_metrics(simulation_id: str, scenario_id: str | None = None) -> SimulationMetrics
get_metrics(simulation_id: str) -> SimulationMetrics
compare_metrics(simulation_ids: list[str]) -> dict
```

### 4.5 SignalTrackingService

文件：

```text
backend/app/services/signal_tracking_service.py
```

职责：

- 管理项目追踪关键词和信号源。
- 调用现有 `web_search_provider`。
- 去重、摘要、打分。
- 生成 `SignalObservation`。
- 写入图谱 episode。

关键方法：

```python
refresh_signals(project_id: str, graph_id: str) -> list[SignalObservation]
list_signals(project_id: str) -> list[SignalObservation]
write_signal_episode(graph_id: str, signal: SignalObservation) -> str
```

### 4.6 ScenarioComparisonService

文件：

```text
backend/app/services/scenario_comparison_service.py
```

职责：

- 聚合多个情景的 metrics。
- 抽取关键路径差异。
- 调用 ReportAgent 或 LLM 生成对比摘要。

输出：

```json
{
  "summary": "...",
  "recommended_scenario_id": "...",
  "metric_table": [],
  "path_differences": [],
  "risk_signals": [],
  "uncertainties": []
}
```

## 5. API 设计

### 5.1 决策结构化

```http
POST /api/decision/context/generate
```

请求：

```json
{
  "project_id": "proj_xxx",
  "simulation_requirement": "推演方向",
  "additional_context": "可选"
}
```

响应：

```json
{
  "success": true,
  "data": {
    "decision_goal": "...",
    "key_variables": [],
    "candidate_interventions": []
  }
}
```

### 5.2 情景管理

```http
GET /api/scenarios?project_id=proj_xxx
POST /api/scenarios
GET /api/scenarios/{scenario_id}

POST /api/scenarios/{scenario_id}/run
```

### 5.3 指标评估

```http
GET /api/simulation/{simulation_id}/metrics

```

```http

```

请求：

```json

  "project_id": "proj_xxx",
  "scenario_ids": ["scn_a", "scn_b"]
}
```


## 7. 报告工具扩展

在 `ZepToolsService` 新增：

| 工具 | 作用 |
| --- | --- |
| `signal_search` | 搜索外部信号 |
| `evidence_matrix` | 输出假设、证据、反证、变量 |
| `scenario_compare` | 对比多个情景指标和路径 |
| `probability_assess` | 基于多次运行结果给出经验概率 |

在 `ReportAgent` 新增报告模式：

- `prediction_report`：现有未来预测报告。
- `decision_report`：单情景决策报告。
- `comparison_report`：多情景对比报告。
- `signal_update_report`：信号更新报告。

## 9. 风险与控制

| 风险 | 控制 |
| --- | --- |
| 功能过大 | 分 MVP、增强版、长期版 |
| LLM 输出不稳定 | 所有 JSON 使用 schema 校验和兜底 |
| 多情景运行成本高 | 支持短轮次、批量限制和成本提示 |
| 外部信号误报 | 保留来源、置信度、人工确认 |
| 概率被误读 | 明确标注经验概率，不等同真实概率 |
| 破坏现有流程 | 默认保留单情景模式 |
