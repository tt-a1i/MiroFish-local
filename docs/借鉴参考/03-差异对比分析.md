# Decitron 与 MiroFish-local 差异对比分析

## 总体结论

Decitron 的公开定位是“复杂系统通用决策推演系统”，MiroFish-local 当前是“传播推演专用系统”。两者共享一部分底层思想：结构化事件、多主体推演、路径演化、报告输出和持续校准。但二者在产品边界、数据闭环、指标评估和决策抽象上存在明显差异。

更准确地说：

```text
Decitron = 通用决策推演叙事 + 信号感知 + 世界建模 + 多路径比较 + 方案量化
MiroFish-local = 传播/舆情垂直推演 + 图谱 + 人设 Agent + 社交仿真 + 报告/互动
```

MiroFish-local 不必照搬通用决策机，而应将 Decitron 的关键结构借鉴到传播推演赛道，形成更聚焦、更可落地的“传播推演决策引擎”。

## 产品定位差异

| 维度 | Decitron | MiroFish-local | 差异判断 |
| --- | --- | --- | --- |
| 产品目标 | 面向复杂系统的 AI 决策引擎 | 多智能体传播/舆情/社会动态仿真 | MiroFish 更垂直，也更易落地 |
| 核心用户 | 金融、战略、地缘、公共治理、产业研判等决策者 | 舆情分析、危机公关、传播研究、社会科学模拟用户 | 用户重叠在舆情/公共治理 |
| 核心问题 | 哪个选择更优、风险如何传导、未来路径如何变化 | 某事件如何传播、哪些群体如何反应、舆情如何演化 | Decitron 更强调行动选择 |
| 产品输出 | 决策空间、路径比较、概率/风险、行动建议 | 模拟时间线、图谱、预测报告、Agent 对话 | MiroFish 报告需升级为决策报告 |

## 数据与信号差异

| 维度 | Decitron 公开能力 | MiroFish-local 当前能力 | 缺口 |
| --- | --- | --- | --- |
| 外部信号 | 全球信号感知，持续捕捉政策、市场、产业、舆情变化 | Step1 一次性 Web Search 或文件输入 | 缺少持续订阅、去重、版本和触发机制 |
| 事件链 | 基于时间序列还原事件链，识别因果路径 | SeedAnalysis 可生成新闻式全记录，图谱可抽取关系 | 缺少信号级事件链重建和增量更新 |
| 变量抽取 | 提炼核心变量和隐含机制 | 模拟配置中有活跃度、立场、影响力、平台权重 | 缺少统一变量注册表和变量影响评估 |
| 历史复盘 | 基于数百起全球事件深度复盘的叙事 | 可基于上传/搜索材料构建单项目图谱 | 缺少跨项目案例库和回测库 |

MiroFish-local 的优势是已经有 Graphiti/Zep 图谱和 episode 写回能力。只要把外部信号也写成 episode，就能快速接近 Decitron 的“信号追踪”形态。

## 建模与推演差异

| 维度 | Decitron | MiroFish-local | 缺口 |
| --- | --- | --- | --- |
| 世界模型 | 公开资料强调世界建模、事件图谱、概率建模 | 图谱 + OASIS 社交环境 | 缺少明确 State-Action-Outcome 中间层 |
| 主体建模 | 多方参与者行为与策略互动 | 图谱实体转 OASIS Agent，人设具备行为倾向 | MiroFish 在传播主体上更具体 |
| 行动空间 | 投资、政策、战略、外交、传播等多领域行动 | 发帖、评论、点赞、转发、搜索、关注等社交动作 | 行动空间绑定社交平台 |
| 干预方式 | 多路径、多策略、多情景 | 重新推演或修改配置后重跑 | 缺少干预点和策略版本管理 |
| 推演结果 | 多阶段演化路径、风险拐点、行动建议 | 动作流、时间线、报告、Agent 访谈 | 缺少路径分支图和结果对比表 |

MiroFish-local 适合先聚焦传播场景做深：把“发布声明、调整回应时机、引入 KOL、平台降权、反谣言投放”等转化为传播干预动作。

## 概率与评估差异

| 维度 | Decitron | MiroFish-local | 缺口 |
| --- | --- | --- | --- |
| 概率建模 | 强调概率信念建模、贝叶斯更新、成功概率评估 | 暂无预测概率字段，`info_confidence` 仅用于实体真实性 | 缺少概率模型和校准数据 |
| 指标评估 | 方案收益、风险、成功概率 | 轮次、动作数、Agent 统计、报告文本 | 缺少指标评估服务 |
| benchmark | 公众号声称 PolyBench 指标 | 暂无标准回测体系 | 缺少历史案例和预测留痕 |
| 结果比较 | 多路径与多情景评估 | 可手动多次运行，但缺少系统化对比 | 需新增 `ScenarioComparison` |

短期不建议直接追求复杂概率模型。更稳妥的路径是先建立指标评估，再用多次仿真结果估计经验概率，最后再做贝叶斯更新。

## 报告与交互差异

| 维度 | Decitron | MiroFish-local | 缺口 |
| --- | --- | --- | --- |
| 报告目标 | 决策报告、风险路径、方案建议 | 未来预测报告、章节式分析 | 报告结构需决策化 |
| 证据机制 | 公开资料强调信号、路径、变量 | ReportAgent 可调用图谱检索和访谈工具 | 缺少证据矩阵和反证清单 |
| 后续追踪 | 持续跟踪不同选择和信号变化 | Step5 可对话和问卷，但不自动更新推演 | 缺少追踪任务和再推演闭环 |
| 用户体验 | 官方页面强调“感知-建模-推演-决策” | 当前是五步线性流程 | 建议升级为项目工作台 + 情景中心 |

## 前端信息架构差异

MiroFish-local 当前是线性五步流程：

1. 事件背景
2. 推演方向
3. 图谱构建
4. 环境搭建
5. 模拟、报告和互动

Decitron 更接近循环型工作台：

```text
信号 -> 建模 -> 推演 -> 决策 -> 追踪 -> 更新
```

建议 MiroFish-local 升级为：

```text
事件图谱 -> 情景设计 -> 运行监控 -> 结果洞察 -> 互动验证
```

其中：

- Step1 增加决策问题结构化。
- Step2 增加情景设计、多情景版本和概率校准。
- Step3 增加信号追踪和关键路径面板。
- Step4 增加情景对比报告。
- Step5 增加互动结果回写校准。

## 可直接复用的 MiroFish 优势

虽然 Decitron 的公开叙事更宏观，但 MiroFish-local 有几个非常实际的优势：

1. 已有可运行的多 Agent 社交仿真引擎，不需要从零构建模拟环境。
2. 已有本地图谱/记忆模式，适合做私有化传播推演。
3. 已有行动日志和 timeline，适合做指标评估。
4. 已有报告 Agent 工具调用框架，适合扩展新工具。
5. 已有 Step5 深度互动，适合做专家校准、问卷校准和用户反馈闭环。

## 差异带来的战略建议

不要把 MiroFish-local 改成泛化的 Decitron。更好的策略是：

1. 在传播推演领域做到比通用决策机更具体。
2. 把 Decitron 的“信号、变量、路径、概率、方案、追踪”六个概念垂直化。
3. 将传播干预作为核心卖点，而不只是传播预测。
4. 建立可视化的情景对比和报告结构，让用户能直接做决策。

目标产品名称可以是：

- 传播推演决策引擎
- 舆情干预推演平台
- Social Decision Simulation Engine
- NewsPower Decision Lab
